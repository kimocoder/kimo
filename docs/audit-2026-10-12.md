The audit covered the Bash dispatcher and embedded Python, the Gemini/Ollama shim, installation and CI configuration, and all existing shell test suites. Changes were limited to the subsequently requested quota feature, its documentation/tests/installation wiring, and this report. Existing workspace changes were preserved. Findings below remain open outside that feature.

Bandit was unavailable; no claim is made of a complete automated security scan. Live Grok, Kimi, and Claude quota probes succeeded after the follow-up work below; other provider compatibility remains subject to the earlier audit's limits.

## Highest-priority findings

### 1. `sync` does not copy the source model

**Priority: high. Confirmed by HTTP fixtures.** In `kimo`, `_sync_single_model` reads source/destination tags but ultimately calls `cmd_pull` on the destination. Ollama `/api/pull` downloads from the registry, not the named source host. Source-only/custom models cannot be replicated this way; a registry tag can resolve to different content. The command reports success without verifying the resulting destination digest.

The fixture observed source/destination tag reads followed only by a destination registry pull, and a success message despite a different destination digest. Implement actual manifest/blob transfer or an appropriate source-to-destination mechanism, then verify the destination digest before claiming synchronization. Regression tests should cover a source-only model and same-name/different-digest models.

### 2. Tagged model names are parsed incorrectly by the Gemini shim

**Priority: high. Confirmed.** `lib/ollama-gemini-shim.py`, `do_POST`, uses `([^:]+):([a-zA-Z0-9]+)` for the model/method path. `/v1beta/models/custom:latest:streamGenerateContent` becomes model `custom` and method `latest`. The upstream request therefore uses the wrong model and disables streaming. The expression also accepts trailing path material and unrecognized methods.

Split at the final method delimiter and validate a full path against an explicit method allowlist. Cover model tags, namespaced names, both supported generation methods, and invalid paths.

### 3. The Gemini shim loses tools and multimodal input/output

**Priority: high. Confirmed.** The shim translates only text parts. Function declarations, function responses, and image input are discarded; upstream `tool_calls` are not translated into Gemini function calls. A fixture containing tools/images reached Ollama with an empty text message; a tool-call response became empty text in the Gemini response.

This affects the core ability of an agent to operate on code. Implement round-trip function-call/tool-result translation and supported image handling, or reject unsupported content explicitly. Verify a complete tool loop rather than a text-only reply.

### 4. JSON pull failures can exit successfully

**Priority: high for automation. Confirmed.** `cmd_pull` prints each JSON event and immediately continues before checking its `error` field. A fixture stream containing `{"error":"fixture download denied"}` produced that JSON and exited zero.

Emit the error event while also returning nonzero; require an explicit terminal success when appropriate. Test streamed upstream errors and premature stream termination in both text and JSON modes.

### 5. Token rotation can claim success after Apache reload fails

**Priority: high for operational reliability. Confirmed with temporary token files and mocked services.** `cmd_rotate_token` ignores reload failure using `|| true`, then sets `apache_reloaded=true`. With `--no-verify`, the token file changes and the command reports success even though Apache did not reload. Clients can be handed a token the running proxy does not accept.

Treat reload failure as a failed rotation, restore/render the previous token, and report the actual service result. Test reload failure independently of render/config-test failures. Tests must always mock service-management commands even when they use a temporary token file.

## Other confirmed issues

| Issue | Evidence and impact | Suggested correction |
| --- | --- | --- |
| Shim advertises `countTokens` but performs generation | The model list includes `countTokens`; a fixture request reached the generation handler and returned a generation response. | Implement counting accurately or remove the advertised capability and reject that method. |
| Shim crashes on a valid JSON body with the wrong shape | Sending a JSON list caused a disconnected HTTP request rather than a structured 400 response. Content-length parsing is also unchecked. | Validate body type/shape, method, and bounded content length before translation. |
| `--local search` still queries remote hosts | The fixture recorded both local and remote `/api/ps` and `/api/tags`, and results from both hosts. `cmd_search` handles custom/multi modes but defaults local/remote modes to both. | Honor local/remote host mode explicitly and assert request destinations. |
| Host URLs with path prefixes are malformed | `--host https://example.invalid/ollama` becomes `https://example.invalid/ollama:11434`. | Normalize with URL parsing; preserve explicit HTTP(S) default ports and append any inferred port to the authority, never the path. |
| Global parser consumes child CLI flags after `--` | `launch qwen ... -- --version` prints the kimo version instead of invoking Qwen; `--json` disappears from child arguments. | Introduce a real passthrough boundary and test the child's recorded argv. |
| Configuration precedence differs from documentation | File `no_color=true` is reset by parser initialization; file `web_engine` overrides `KIMO_WEB_ENGINE`. | Initialize defaults before configuration and consistently apply file < environment < explicit options. |
| Config loader and validator disagree | Quoted values and semicolon comments are accepted by the loader but rejected by `config validate`; invalid URL/engine values can pass validation. | Share parsing/validation rules and validate each supported field. |
| Configuration values can inject additional entries | A newline inside `config set default_model` writes an additional `remote_url` entry. | Reject multiline/control-character values or use a structured serialization format. |
| Missing-config JSON is not escaped | A missing config path containing `"` produces invalid JSON in the validation error. | Serialize error objects using a JSON encoder. |

## Test and maintenance improvements

1. **Make failures fail the build.** `make check` prefixes `bash -n` with `-`, ignoring its failure and printing "Bash syntax OK". `make lint` silently succeeds when ShellCheck is missing. `backup_prune_test.sh`, `gh_guard_test.sh`, `pull_json_test.sh`, and `web_url_esc_test.sh` can print `FAIL` without accumulating a failing exit status. Make checks enforce their prerequisites and centralize assertion failure handling.
2. **Expand protocol/behavior tests.** Current successful launch fixtures do not prove Gemini tool compatibility, digest-correct synchronization, JSON failure propagation, or parser passthrough. Add targeted contract tests for these failures before implementation changes.
3. **Review concurrent configuration overrides.** Grok/Antigravity launchers use per-process claim files and temporary edits to shared settings. Static inspection suggests interleaved sessions can leave an override restored incorrectly or stranded after a stale claim; this was not reproduced and should be verified with overlapping sessions and interrupted processes.
4. **Strengthen installer reproducibility.** Several CLI installers execute remotely fetched shell scripts directly. Pin versions/artifacts where available and verify checksums/signatures. Existing GitHub CLI checksum verification is a useful pattern. This is a hardening recommendation, not evidence that an installer is compromised.
5. **Reduce duplicated embedded Python.** Host routing, HTTP errors, JSON serialization, configuration parsing, and environment construction are repeated inside the large Bash file. Move well-defined adapters into testable helpers gradually; avoid a broad rewrite while the behavior above lacks regression coverage.

## Follow-up: Grok and Kimi account quotas

Grok now reads its native `_x.ai/billing` method over `grok agent stdio`, without creating a session or starting an inference request. It reports percentage credit usage, period/reset, plan, on-demand spending/cap, prepaid balance, and available history. Empty monetary protobuf objects represent zero; absent fields remain unknown. The native client handles authentication.

Kimi now reads the managed provider's configured API, OAuth host, and matching credential slot. The previous hardcoded mainland endpoint/default credential selection caused authentication failures for the signed-in global account. Global, mainland, and explicit endpoint overrides now follow the client's slot scoping. Named account windows take precedence over duplicate legacy limits, and extra-usage wallet amounts use the API's fixed-point currency conversion.

Kimi OAuth can refresh an expiring or rejected token once, using the native refresh lock, private temporary storage, and atomic replacement. `--no-refresh` disables this behavior. Regression fixtures cover concurrent refresh coalescing, stale locks, rejected/incomplete refresh responses, storage failure, timeouts, and logout during refresh.

Live `./kimo quotas grok --json` and `./kimo quotas kimi --json` both returned `online` with account scope. At the check, Grok reported 0% included weekly credits remaining; Kimi reported 100% of its 5-hour quota and 9.55%/9.58% of monthly total/code quotas remaining. Both wallets had zero balances. These are point-in-time observations, not guaranteed current balances. A subsequent `kimo quotas all` check found the global installation was outdated; `make install` updated `/usr/local/bin/kimo` and its quota helper to match the workspace, and the installed command then succeeded with both Grok and Kimi online.

## Follow-up: Claude authentication and stats

The Claude quota adapter sent an expired cached OAuth access token directly to `/api/oauth/usage`, resulting in HTTP 401. Credential metadata confirmed expiry; the installed Claude client's `auth status` command recognized the account but did not refresh the token.

The adapter now refreshes file-backed OAuth within the native five-minute expiry threshold and retries once after an unexpected HTTP 401. It follows the installed Claude client's JSON refresh protocol and coordinates its current/legacy refresh locks plus secure-storage write lock. Private atomic persistence preserves the rest of `.credentials.json`, including MCP credentials. Explicit environment tokens retain precedence and never switch to another cached account; `--no-refresh` applies to both Claude and Kimi.

Stats now handle modern scoped limits, legacy windows, model filtering, reset times, plan/tier metadata, and extra-usage monetary limits. Currency conversion matches the native formatter, and disabled/unlimited spending caps retain unknown remaining allowances. Live Claude quota data returned `online`, with 97% of its five-hour quota and 100% of its weekly quota remaining at the first check. The fix was installed globally; `kimo quotas all` subsequently returned Claude `online`, with 93% five-hour and 99% weekly remaining at 15:09 UTC. All 96 adapter/protocol tests, 53 dispatcher assertions, syntax, lint, and staged installation checks passed.
